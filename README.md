# 🎉 모여라 게임판 (PartyGame)

예능에서 보던 단골 게임 7종을 모은 파티+솔로 게임.
**웹과 안드로이드 앱이 같은 코드 하나**로 돌아간다.

- ▶ **바로 하기(웹)**: https://yongminlee2.github.io/partyGame/
- 📱 **안드로이드**: 같은 웹 번들을 내장한 WebView 앱 (플레이스토어 출시 준비)
- 서버 없음 · 계정 없음 · 광고 없음 · 수집하는 개인정보 없음

## 게임 목록

| 게임 | 혼자 | 다같이 | AI 역할 |
|---|:---:|:---:|---|
| ⭐ 연예인 퀴즈 (초성·사진) | O | O | 정답 속도 대결 상대 |
| 📜 사자성어 뒷글자 | O | O | 정답 속도 대결 상대 |
| 🙆 몸으로 말해요 | - | O | - (기울기 센서 판정) |
| 💣 폭탄 초성게임 | O | O | 사전 기반 단어 대결 |
| 🤥 라이어 게임 | O | O | AI 4명 중 라이어 찾기 |
| 🎡 복불복 룰렛 | - | O | - (도구) |
| 📷 사진 퀴즈 만들기 | - | O | - (내 사진으로 출제, 기기 내 영구 저장) |

AI는 전부 **내장 알고리즘**(난이도별 응답속도·정답률 파라미터, 사전 검색)이라
서버·API 키 없이 오프라인에서도 동작한다.

## 아키텍처

```
web/          게임 본체 — 순수 HTML/JS/CSS (빌드 도구·외부 라이브러리 0개)
├── js/core/  라우터·저장·사운드(WebAudio 합성)·한글초성·퀴즈엔진·위키로더·사진효과
├── js/ai/    AI 대전 상대 (지수분포 응답시간 + 난이도별 정답률)
├── js/games/ 게임 7종 (1게임 1파일)
└── data/     JSON 데이터 (전부 자체 제작 또는 CC0)
app/          Android WebView 래퍼 (WebViewAssetLoader, web/을 assets로 내장)
tests/        node:test 순수 로직 테스트 44개
tools/        데이터 빌드·검증 스크립트
```

- **웹 배포**: main 푸시 → GitHub Actions(테스트+검증 통과 시) → gh-pages 브랜치 → GitHub Pages
- **앱**: `gradlew assembleDebug` 시 `web/` 전체가 assets로 복사돼 오프라인 동작.
  ES 모듈이 file://에서 안 돌기 때문에 `WebViewAssetLoader`(https 가상 오리진)를 쓴다.

## 저작권·초상권 분석 (연예인 사진 문제)

예능 게임 앱에서 제일 위험한 게 연예인 실물 사진이다. 결론과 근거:

| 항목 | 판단 | 근거 |
|---|---|---|
| 게임 형식(포맷) 자체 | 안전 | 게임 규칙·아이디어는 저작권 보호 대상이 아님 |
| 프로그램명·로고 | 사용 금지 | 상표권·부정경쟁방지법 — 앱 어디에도 방송 프로그램명 없음 |
| 연예인 이름·직업·대표작 | 안전 | 사실 정보는 저작권 대상 아님 |
| 인터넷 사진 무단 수록 | 위험 → **미수록** | 사진 저작권(촬영자) + 초상권·퍼블리시티권(본인) |
| 위키피디아 사진 실시간 로딩 | 채택 | 위키 사진은 대부분 위키미디어 커먼즈 자유 라이선스. 앱은 저장·재배포하지 않고 출처를 표기 |
| Flickr CC 사진 | 기각 | 무단 재업로드(라이선스 세탁)가 많아 신뢰 불가 |
| AI 캐리커처 변환 | 기각 | 생성 서버가 필요하고, 원본 사진 라이선스 문제도 그대로 남음 |
| 모자이크·블러 변환 | 채택 | 클라이언트 canvas 처리. 오히려 "점점 선명해지는" 퀴즈 재미 요소가 됨 |
| 실루엣 변환 | 기각(설계 변경) | 직사각형 사진을 어둡게 하면 그냥 검은 상자가 됨 → 블러로 대체 |

사진 모드 동작: 위키피디아 REST API(`/page/summary/{제목}`)로 실시간 로딩 →
canvas 모자이크(8→1단계 점진 공개) → 정답 공개 시 원본+출처 링크 표시.
오프라인·로딩 실패 시 해당 라운드는 초성 퀴즈로 자동 전환. **저장소·APK 어디에도 사진 파일이 없다.**

기타 데이터: 사자성어 뜻풀이·라이어 설명·제시어는 전부 직접 작성.
단어 사전은 WordChain 프로젝트에서 검증한 CC0 한국어 단어 목록을 초성 인덱스로 변환.
효과음은 WebAudio 오실레이터 합성(음원 파일 0개).

## 빌드·실행

```bash
# 웹: 정적 서버면 뭐든 됨
python -m http.server 8080 --directory web

# 테스트 + 데이터 검증
node --test
node tools/validate-data.mjs

# 데이터 재생성 (원본 수정 시)
node tools/build-idioms.mjs
node tools/build-celebs.mjs
node tools/build-choseong-dict.mjs   # WordChain 사전 필요

# 안드로이드 APK
./gradlew assembleDebug   # → app/build/outputs/apk/debug/
```

## 개발일지 (2026-07-28)

하루 만에 설계→구현→배포까지. 태스크 단위 기록:

1. **설계·계획** — 브레인스토밍으로 요구사항 확정(웹+앱 단일 코드, AI 솔로 모드,
   사진 3안 검토). 스펙과 20개 태스크 계획서 작성.
   [스펙](docs/superpowers/specs/2026-07-28-party-game-design.md) ·
   [계획](docs/superpowers/plans/2026-07-28-party-game.md)
2. **뼈대** — hash 라우터(파라미터 파싱 테스트), localStorage 래퍼, WebAudio 효과음 5종,
   한글 초성 유틸(유니코드 분해), 데이터 스키마 검증기.
   *배운 것: Windows에서 `node --test tests/`는 디렉토리 인자를 못 받는다 — `node --test`로 자동 탐색.*
3. **데이터 제작** — 사자성어 417개(난이도 3단계, 뜻 직접 작성), 연예인 325명(구설수 있는
   인물은 넣지 않음, 힌트는 사실만 3단계), 몸으로말해요 제시어 1010개(6카테고리),
   라이어 세트 100개(정상 설명 4+어긋난 설명 2), 초성 사전 124쌍(검증용 6.4만 단어 + AI용 흔한 단어).
   *성어·이름의 오타 방지를 위해 front/back·초성은 손으로 안 쓰고 빌드 스크립트가 계산.*
   *실수 사례: "파죽만리"라는 존재하지 않는 성어를 썼다가 자체 검토에서 잡음. "시행착오"는 고사성어가 아니라 교체.*
4. **퀴즈 엔진 + AI** — 라운드 상태머신(기본 100점, 힌트당 -30), AI는 지수분포 응답시간
   (쉬움 평균 12초/정답률 50% ~ 어려움 5초/90%). 통계 테스트(2000회 샘플 ±30%)로 검증.
5. **게임 7종 구현** — 전 게임 순수 로직은 node:test 44개로 커버. 브라우저 실동작 확인.
   *배운 것 1: 위키피디아 이미지는 CORS 헤더를 줘서 `crossOrigin=anonymous`로 canvas에
   그려도 taint되지 않는다 (getImageData로 확인).*
   *배운 것 2: 룰렛의 requestAnimationFrame은 탭이 백그라운드면 아예 멈춘다 —
   setTimeout 안전장치로 결과는 반드시 나오게 처리.*
   *배운 것 3: 몸으로말해요 기울기는 세로 파지 기준 beta각(중립 75~105°)에
   히스테리시스를 걸어야 한 번 숙임에 한 번만 판정된다.*
6. **배포** — GitHub Actions로 테스트 통과 시에만 배포.
   *막힌 것: `actions/configure-pages`의 `enablement: true`는 기본 GITHUB_TOKEN 권한으론
   Pages를 못 켠다(관리자 권한 필요) → gh-pages 브랜치 방식(peaceiris/actions-gh-pages)으로
   전환 + 로컬에서 `git subtree split`으로 첫 브랜치를 만들어 즉시 라이브.*
7. **사진 퀴즈 영구 저장** — 처음엔 메모리 전용이라 앱을 닫으면 사진이 사라졌다.
   IndexedDB에 Blob으로 저장하도록 개선(localStorage는 용량이 작아 사진에 부적합).
   여전히 기기 밖으로는 안 나가고, ✕ 버튼으로 즉시 삭제 가능. 새로고침 후에도
   사진·정답이 유지되는 것을 검증.
8. **안드로이드 래퍼** — WordChain의 AGP 9.2.1/Gradle 9.4.1 구성 재사용.
   WebViewAssetLoader로 assets 서빙(ES 모듈 때문에 file:// 불가), 외부 링크는 브라우저로,
   뒤로가기는 WebView 히스토리 연동. `copyWebAssets` 태스크가 빌드마다 web/을 assets로 복사.
